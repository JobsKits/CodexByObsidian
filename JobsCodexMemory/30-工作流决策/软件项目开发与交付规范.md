- 三级验收依次为基础可运行、可商用、工业化；本期确认范围须完整闭环，不能以未完成功能交付。较高等级包含较低等级要求，性能与工程质量采用可检查的项目指标。

- 各目标操作系统有对应部署文档和入口，写明最低／推荐机器配置、环境版本、步骤及脚本工作流；面向非技术用户减少文字输入。
- macOS 最新正式稳定版及 Windows 10 以上的已验证桌面组合提供本地部署＋内网穿透，服务临时测试、联调及控制云费用；具体版本、穿透服务和安全边界按项目核验。
- iOS 原生采用 OC 时，以 OC 新工程 `JobsOCBaseConfigDemo@ByPods` 为蓝本；采用 Swift 时，以 `JobsBaseConfig@JobsSwiftBaseConfigDemo` 的 UIKit 工程为蓝本。尽可能复用 JobsByPods，使用链式＋点语法 DSL，Podfile 与 Podfile.deps 解耦，并挂载安装后必要脚本；OC 用 Masonry／YTKNetwork，Swift 用 SnapKit／JobsNetworking。脚本真实时机按 hook 区分，工程写盘后的收尾采用 post_integrate。来源：用户六条明确要求，2026-11-02，confirmed。

### 2.2、<span id="project-directory-layers">统一目录与技术路线分层</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- 来源：用户于2026-11-03明确要求写入“从0～1软件开发”Skill并应用陈泉羽项目；状态 confirmed；适用范围：该 Skill 的项目工程规划、实现与目录整理；创建／更新2026-11-03。
- Git 根并列 `代码/`、`测试/`、`需求/`、`部署/`；代码内按 `前端/`、`后端/` 分层。前端先分 PC端、移动端、后台管理端及实际需要的微信小程序／独立Web，再分已选跨平台技术或原生平台；不为模板补空工程或改变已确认方案。后端集中接口契约与后端代码，部署按操作系统集中保存。用户2026-11-03进一步明确把部署从代码中提到外层，并应用李林哲与陈泉羽项目；原 `代码/部署/` 形态为 superseded。入口、相对寻址、测试、文档与代码地图必须同任务同步；运行数据不随部署提层自动迁移。
- 不保留项目自维护 `artifacts/`；已有内容先盘点迁出，发布产物归对应 `dist/`，测试证据归外层 `测试/`。共享业务用包／模块依赖，不复制整套代码；语言工具链内部标准目录保留。
- 测试目录同样按前端／后端／部署职责归类，前端再镜像产品端与实际技术；单元、集成、端到端是各职责内的验证方式，不能用顶层“集成”混放不同职责用例。公共运行器、计划与跨组摘要可在公共位置保留，测试体不重复复制。来源：用户于2026-11-03在陈泉羽项目明确补充，状态 confirmed。
- `代码/`、`测试/`、`需求/` 三个主目录一级仅保留 `README.md` 和目录；本级及同目录的完整说明正文按[[10-用户画像/长期偏好#single-readme-per-directory|同目录README原则]]融合，非说明资料和附件按实际职责归档。旧“公共计划报告可散放主目录”及“默认同主题原稿／阅读版／导航文档并列”的形态为 `superseded`；语言工程内部固定文件及 Git 根必要配置按工具约定保留。来源：用户2026-11-03明确要求并补充README收口原则，状态 confirmed；主规则为 `jobs-software-project/软件项目开发与交付规范.md#main-directory-material-layout`。
- 目录大小写及显示名称遵从[[10-用户画像/长期偏好#macos-directory-naming|MacOS 与英文目录首字母规则]]；自维护发布目录现统一 `Dist/`，前述 `dist/` 仅保留为旧形态或不可配置的工具输出例外，不扩大为所有生成目录的改名授权。来源：用户2026-11-03补充，状态 confirmed；实际迁移保留包身份与平台固定布局。
- 细则唯一维护于 `jobs-software-project/软件项目开发与交付规范.md#project-directory-layout` 及相邻外置测试条款；运行态与备份态按现行即时同步协议维护。具体迁移同步源码、配置、构建、测试、部署、文档与忽略规则，验证边界分别记录。
