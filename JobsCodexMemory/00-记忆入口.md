## 四、当前核心约束

- Codex 任务开始前先扫描本 Vault 结构，再读本入口及命中笔记。
- Codex 全局指导以 `JobsCodexConfigs/AGENTS.md` 为标准源；用户级 Skills 以远端为 `JobsKits/JobsSkills` 的 `/Users/jobs/.agents/skills` 现行工作树为标准源和最大集。`JobsCodexConfigs/skills` 只作为父仓子模块挂载，不得反向覆盖现行工作树。
- `/Users/jobs/.agents/skills` 中指向外援 Skill 的软链接使用精确 `.gitignore` 规则排除，同目录 `README.md` 必须保留上游来源、版本基线和链接映射。
- 任务中只沉淀长期规划、稳定偏好、工作流决策和可复用项目约束。
- Git 仓库中名为 `work/` 的本地生成目录统一用仓库 `.gitignore` 排除；已被跟踪时先核实内容，再仅从 Git 索引移除并保留本地文件。
- 每天凌晨 1 点由 Codex 自动化复盘最近任务并同步新增记忆。
- 每周日凌晨 2 点由 Codex 自动化分别审计 `JobsCodexConfigs/AGENTS.md` 与现行 `JobsSkills` 工作树，并核对子模块指针；去重只能消除等价表达，不能删除触发条件、禁止边界、例外、验证、中文顿号习惯或固定专有名词链接。
- Shell 脚本使用目标工具前必须验证当前执行路径的完整依赖链；每层按“发现、健康检查、条件式修复、刷新环境、二次复检”闭环，只修复缺失或损坏分支，复检失败立即停止下游业务。
- 中文 Markdown 文档的数字次序使用 `1、` 而不是 `1.`；独立技术文档正文首次出现 [**Swift**](https://www.swift.org/) 等固定专有名词时使用对应官方链接，代码、路径和命令字面量除外。
- 面试题文档优先突出问题、核心回答和实战干货；追问必须逐题同步给答案，面试官视角保留但默认收起或视觉降级。
- 不落库密码、Token、私钥、Cookie、临时闲聊和未验证推断。
- 所有代码任务默认只修改 Jobs 自有或已明确接管维护的源码；第三方 Pod、手工第三方、供应商 / 生成代码和所有权不明确的文件一律排除，只有用户明确点名授权后才进入。
- 查找、下载或补充图片、图标及其它 UI 视觉素材时，统一先从 iconfont 查找；确实没有合适素材时再说明并征求其它来源。
- Jobs iOS 三仓的控制器销毁 Toast 由设置页持久化开关统一管理，关闭提示不影响调试日志与清理流程。
- Jobs iOS 三仓 Demo 列表的悬浮时间按钮由设置页持久化开关统一管理；长按隐藏后必须可从设置重新开启。
- Jobs iOS 三仓 Demo 列表悬浮时间按钮的长按隐藏确认弹窗必须直接展示为普通系统 Alert，不进入导航容器，不显示导航栏或返回按钮。
- Swift 传感器 Demo 以人的动作反馈为主表达，三轴原始数据只作为辅助信息。
- OC / Swift 开屏页是宿主页面上的子控制器覆盖层，没有导航栏和返回键，不存在“隐藏返回键”逻辑；倒计时未结束时点击右上角按钮必须立即移除开屏覆盖层；右上角按钮首帧必须已经是胶囊圆角，并通过 `UIButton` 专用 Jobs 封装写入 `UIButtonConfiguration.background`，不能把普通 `UIView` / Layer 圆角当成新按钮管线的最终实现。
- Swift、OC 新项目和 OC 老项目的设置页必须完整提供本地图片、本地 GIF、远程图片、本地视频、远程视频五种开屏内容选择；展示开关与内容类型分开持久化，启动入口按下一次设置构造真实开屏配置。
- Jobs iOS 三仓设置页的开屏内容、应用语言和 Demo 列表主 / 副标题策略统一使用一级 Cell 展示当前值，点击后在同一表格伸缩展开二级选项；列表文字策略包含一般裁切、省略号、缩小字体、连续跑马灯和左右来回滚动，长短文本在深浅色下都必须与同层普通 UILabel 保持同色。
- Swift、OC 新项目和 OC 老项目选用远程开屏视频时，只播放已完整缓存的远程文件；未缓存时立即播放本地视频兜底，并在倒计时按钮左侧提示“仅在 Wi-Fi 环境下下载视频”。预加载任务由缓存单例持有，不能因倒计时结束或手动移除开屏而取消；失败后持续退避重试，待下载 URL 跨启动恢复直至成功。
- OC AppDoor-2 是全屏横滑认证页：不展示系统 / GK 导航栏、导航标题和顶部返回按钮；Logo 只属于初始登录态且保持正方形等比显示，注册 / 忘记密码态隐藏；普通表单输入文字靠近左侧图标，手机号号码区紧跟 `+86`，注册按钮下固定提供“返回首页”。AppDoor-1 的“记住我 / 忘记密码”字号与 AppDoor-2 保持一致，“去注册 / 返回登录”字体与“返回首页”保持一致；两套页面的验证码倒计时文案必须完整多语言化并居中显示。
- OC 刷新体系保持状态机与动画表现层解耦：`JobsOCRefresher` 只托管统一协议，具体素材与品牌动画归 `JobsFuseAnimation`，并支持挂载后的原位热替换。
- Jobs iOS 三仓 Demo 根列表中的 Label 能力统一使用独立 `Label` section 展示和管理，不再混入 Timer 或通用 UI section。
- Jobs 自建 Pod / DSL 必须在封装内部消化 Apple API 过期与版本差异，不向 Swift、OC 新工程或 OC 老工程的调用方外溢 deprecated 警告。
- Jobs iOS UI 默认预埋可修改引用：进入页面层级、绑定约束 / 事件 / 代理或可能后续重配的对象，Swift 提升为类型属性，OC 提升为属性 + 懒加载 getter；重复动态 UI 由强类型集合属性持有，不长期留在方法局部变量中。
- OC 按钮事件默认使用 `onClickBy` / `onClickAppendBy` / `onLongPressGestureBy` / `onLongPressGestureAppendBy` 的 Block 点语法链；`byAddTarget` 仅保留 Target-Action 兼容，新业务调用不推荐使用。
- Jobs iOS 自维护代码的约束布局统一：Swift 主工程与自建本地 Pod 只使用 SnapKit，OC 新、老项目主工程与自建本地 Pod 只使用 Masonry；禁止直接使用系统 `NSLayoutConstraint` / Anchor API。
- Jobs iOS 三仓的 `JobsScreenCapture` 同时承载主动截屏保存、截屏后提示与敏感区域截图保护；两个截屏 Demo 都提供主动截屏触发点，使用相册 `add-only` 权限，系统截屏和按钮截屏分开反馈；Swift、OC 新项目使用本地 Pod，OC 老项目直接集成到主工程 `JobsMixFunc`，不新增 Pod。
- Jobs iOS 三仓的 `switch` 分支必须在每个 `case` 紧邻上方使用同缩进的独立 `///` 写明对应枚举值或业务语义，禁止行尾分支注释；枚举定义处已有注释不能替代使用处注释，规则覆盖新增、修改和存量回归代码。
- Jobs iOS 三仓的 Demo 入口新增或重命名时必须同步全量对账图标映射；缺项、重复或无效图标只做一次诊断与可见兜底，不得用运行时断言让 App 崩溃。
- Swift 视觉滤镜必须在相机 / 相册或录制语境中提供可发现的真实操作入口，不能只作为“打马赛克”内部实现存在；当前照片滤镜入口归 `PhotoAlbumDemoVC`。
- OC 新项目与 OC 老项目安装到设备后的主 App 显示名统一为 `OCDemo`；只调整 `CFBundleDisplayName` 管线，不连带修改产品名、Bundle ID、测试 target 或 Widget 名称。
- Swift / OC 两侧的 `JobsAppDoor@Pods` 在 Xcode `Development Pods` 中统一按 `Core / Pod / Resource / Support Files` 展开；`Core` 下固定为 `登录注册模块公共件`、`JobsAppDoorStyle1`、`JobsAppDoorStyle2`。两套 Style 共用的资源访问、基础内容视图和忘记密码页必须归公共层，图片和视频归 `Resource`，资源包统一命名为 `JobsAppDoorResources.bundle`。
- Jobs iOS 三仓从 Demo 根列表进入的每个导航 / 模态子页面，以及按约定命名的独立 Demo 页面，统一由 Jobs 导航封装在右上角注入全局主题切换按钮；按钮切换全部 Scene 的 Window，保留页面已有右侧业务按钮，不再由各 Demo 重复实现局部主题按钮。
- Jobs iOS 三仓的复杂 Demo 除了真实可见、可操作，还必须提供可发现的架构智慧入口；右上角仍只有一个菜单触发器，主题与页面动作统一收进列表。时时彩 Demo 统一表达为 Model 对应逻辑 Timer、TimerMgr 物理托管、VC 只持有 Scope，并显式展示时间真值、复用保护、精准取消和生命周期治理。
- Jobs iOS 三仓的双端功能对齐 Demo 必须一项功能对应一个独立 DemoVC，并作为独立条目直接接入 Demo 根列表；允许复用无业务分发职责的页面基座，但禁止用 Workbench 聚合页、二级功能按钮或分支状态把多个功能重新塞回同一页面。
- Jobs iOS 三仓的 SceneDelegate 研究统一落为独立可操作 Demo：`AppDelegate` 管进程，`SceneDelegate` / `UIWindow` 按会话独立；状态按 `UISceneSession.persistentIdentifier` 隔离并以 `NSUserActivity` 恢复，禁止全局 SceneDelegate 和 `connectedScenes.first`。不可用动作仍可点击并用当前 Scene 的 Toast 解释，真正系统执行失败才使用 Alert；完整流程优先在 iPad 验证。
- Jobs iOS 三仓中，同一核心能力仅因 `UITableViewCell` / `UICollectionViewCell` 等表现形式不同，不重复占用多个 Demo 根入口；使用一个根入口和只分发同质表现分支的二级列表，各分支仍进入独立 DemoVC，不得聚合不同业务功能。
- Swift 与 OC 对齐 Demo 必须完整复现对应页面的可见结构、交互和状态，不得只做极简单按钮壳；能力分组与标题使用中性业务语义，不标注来源语言。
- Swift、OC 新工程与 OC 老工程的 Jobs 自维护代码中，所有支持 Jobs 点语法 / 链式语法的对象都执行“一镜到底”（亦称“一链到底”），不限于按钮；同一连续配置语义中主接收者只作为链起点出现一次，子对象通过宿主级 DSL / 配置闭包继续回主链。缺 API 时先在真实归属层补齐返回 `Self` 的封装；子类专属 DSL 先于会降级返回类型的父类 DSL，多个 `void` 终止动作分别调用。
- Swift 导航标题包含 `@` 时，按第一个 `@` 拆为主标题和副标题并上下展示；没有 `@` 时维持单行标题。
- Swift 运行时相册照片只能作为 App 内副本管理，不能直接变成桌面 AppIcon；桌面图标必须替换编译期 `Resources/AppIcons/*.icon/Assets/Front.png` 后重新构建安装。
- JobsCommand iOS 打包脚本以不引入 `fastlane` 的原生 iOS 打包工具为长期方向；保留原有 `.app → IPA` 模式，新增能力统一使用经过自检的 `fzf` 选择，高风险 Apple 后台变更仍要求输入完整 `YES`。
- 凡修改 Jobs iOS 底层自建 API，必须在同一任务完成源码、公开入口、README / Demo、工程配置文档和公共 `/Users/jobs/Library/Developer/Xcode/UserData/CodeSnippets` 的同步传播：OC 核对新老工程及两份《OC工程项目框架配置方案@Jobs.md》，Swift 核对对应实现及 `SwiftDoc.md/Swift工程项目框架配置方案@Jobs.md`；没有对应项也要检索并在交付中说明。
- Jobs iOS 三仓的录音与录像 Demo 快门统一使用白色实心内圆、透明间隔和白色外圈；录制期间主体保持白色，计时进度可单独使用红色描边。
- OC 老工程当前文件同步组下新增或平移 `.m` 时，必须同步进入 `PBXFileSystemSynchronizedBuildFileExceptionSet.membershipExceptions` 的实际编译清单；只落盘和公开头可见会导致分类实现不链接，并可能在运行时触发 `unrecognized selector`。
- OC 新、老工程的朋友圈 Demo 使用真实本地图片与预览，点赞 / 评论采用图标加文字；点赞后图标变红且长按显示气泡，评论提供三种模式并与主题动作统一收进右上角唯一列表，页面全部可见元素同步适配深浅色。
- Jobs iOS 三仓的计时器文档统一按 `Timer` / `NSTimer`、`DispatchSourceTimer`、`CADisplayLink`、`CFRunLoopTimer` 四种系统内核说明选型；TimerMgr 只负责稳定标识、去重、精准取消、Scope 生命周期和复用保护，不改变底层精度与系统边界。
- OC 新、老工程主题适配必须覆盖公共导航返回项、背景、主副标题、侧滑抽屉、功能菜单和当前可见控件；主题中心执行绑定回调前先快照弱引用键，禁止直接枚举会被回调反向修改的 `NSMapTable`。
- OC 新工程 Jobs 自建 Pod + 应用 / Demo 与 OC 老工程 Jobs 集成代码的 0 / 1 入参普通功能方法统一返回 JobsBlock，只改表达不改行为；固定 ABI 保留原 selector trampoline 并把内核收入 `jobsXxx` Block 门面，`sharedManager` / `destroySingleton` 使用 `jobsSharedManager()` / `jobsDestroySingleton()` 门面。实例 Block 使用 `@jobs_weakify(self)` / `@jobs_strongify(self)`，`JobsBlock` 底层循环依赖例外除外。批处理不以目录名代替所有权判定，要联查源码与同名头的作者 / 版权。
- OC 新、老工程应用层 / Demo 使用任何 Pod 时，只允许在调用文件同名 `*.h` 中以 `__has_include` 双通道引入 Pod 聚合头；`*.m` / `*.mm` 禁止裸写 Pod 头或内部子头。两工程先全量迁移和静态反扫，再统一编译并集中修错。
- OC 新项目 Jobs 自维护 `*.m` 中的每条 `#import "xxx.h"` 独占一行，相邻的双引号 import 之间不留空行；文件头与导入区、导入区与正文之间仍各保留一个空行。
- OC 新工程与 OC 老工程的唯一架构差异是本地 Pod 集中管理与主工程直接集成；用户只点名一侧时默认同步另一侧。除 podspec、Podfile、聚合入口、Development Pods 与老工程 Xcode 装配等形态差异外，对应 Jobs 自维护源码、API、Demo、资源、行为和文档必须一致。
