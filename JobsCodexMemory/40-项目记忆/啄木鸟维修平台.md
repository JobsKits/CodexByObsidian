## 二、可复用约束 <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- 2026-10-04 用户确认：README 使用低矮横幅，Logo 必须体现“啄木鸟＋维修”融合语义；当前 `README-banner.svg` 为红冠啄木鸟与扳手组合，两份 README 共用该本地资源。
- iOS 主 App target 最后一个 Build Phase `Save Build IPA` 调用 `iOS/ScriptsByDevTools/save_device_ipa_after_build.sh`。模拟器固定输出 `iOS/build/模拟器.ipa`，真机固定输出 `iOS/build/真机.ipa`；真机产物要求有效签名，并通过严格签名校验。
- 脚本先在系统临时目录生成 `Payload/<App名>.app` 并完成 IPA 压缩；成功后清空 `iOS/build/` 全部内容，只留本次平台包。签名或压缩失败时不会先清理旧产物。日志在 Xcode 构建日志和系统临时目录中的 `save_device_ipa_after_build.log`。
- `iOS/build/` 只存一次性 IPA；DerivedData、源 App 和构建中间目录放在外部。模拟器 IPA 不能安装到真机或用于正式分发。具体流程需同时记录在根 `README.md` 和 `iOS/README.md`。
- 自定义 `App/Info.plist` 配合 `GENERATE_INFOPLIST_FILE = NO` 时必须显式声明 `CFBundleExecutable = $(EXECUTABLE_NAME)`。缺少该项会生成有二进制但不能安装的 App，并触发 `MIInstallerErrorDomain / MissingBundleExecutable`。
- 2026-10-03 模拟器构建与连接 iPhone 的真机构建均成功；真机 IPA 签名校验通过，`devicectl` 已将修复后的 `com.jobs.repairmarketplace` 安装到设备。模拟器 IPA 曾验证包含 `Payload/RepairMarketplace.app`。尚未验证 App 启动后的服务联网、Go 编译或 TiDB 连接。

## 三、部署体系决策 <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- 项目根目录下建立 `Deployment/`，其顶层 `README.md` 用精炼、正式的书面表达说明部署动机和总体设计：面向本机开发及华为云、腾讯云、阿里云常见服务器环境，降低部署成本并保证部署路线可迁移。
- `Deployment/Docker/` 与 `Deployment/Kubernetes/` 是同等完整、并行维护的两条部署路线。Docker 是当前优先落地使用的路线，不代表 Kubernetes 仅预留或延期；两条路线共用 Go 源码、应用镜像、运行配置和数据库迁移规则。
- 两条路线都覆盖 macOS、Windows 和常见云 Linux 发行版。Linux 按发行版建立脚本目录，每个发行版入口在运行时检测 `ID`、`VERSION_ID`、CPU 架构并选择对应流程，不按每个小版本复制脚本；支持范围按三家云当前推荐且仍维护的公共镜像版本建立矩阵。
- 部署脚本应覆盖 Ubuntu、Debian、CentOS Stream 及三家云厂商常见的云优化发行版，包括 Alibaba Cloud Linux、TencentOS Server / OpenCloudOS、Huawei Cloud EulerOS 等；每个系统平台脚本目录配套 `README.md`。
- Docker / Kubernetes 运行环境准备与 Go 应用依赖封装分层；Go 编译器及应用运行依赖进入容器镜像，宿主机只准备对应的容器引擎或集群工具。数据库持久化、配置与网络访问边界需在两条路线中分别说明。
- 用户最终确认的部署目标是“启动匹配平台入口，一次完成运行环境准备和后端部署”，优先降低部署开销；Windows 只提供 `.ps1`，不提供 CMD/BAT。由于 Windows 对 PS1 默认双击行为受文件关联和执行策略影响，README 必须引导右键“使用 PowerShell 运行”或从 PowerShell 启动。
- 2026-10-04 已建立 `Deployment/README.md`、Docker 与 Kubernetes 路线 README、共享组件 README，以及 macOS / Windows / Linux 入口 README。Docker / Kubernetes 各包含 17 个 Linux 发行版独立 `deploy.sh`，统一按 `/etc/os-release` 的 ID / VERSION_ID 和 CPU 架构检测，不复制每个小版本的流程。
- 当前 Linux 支持矩阵：Alibaba Cloud Linux 3/4、AlmaLinux 8/9/10、Amazon Linux 2023、Anolis OS 8/23、CentOS Stream 9/10、Debian 12/13、Fedora 43/44、Huawei Cloud EulerOS 2.0、OpenCloudOS 8/9、Oracle Linux 8/9/10、RHEL 8/9/10、Rocky Linux 8/9/10、SLES 15 SP7、TencentOS Server 3.3/4.0、Ubuntu 20.04/22.04/24.04/26.04、openEuler 20.03/22.03/24.03、openSUSE Leap 16.0。Ubuntu 20.04 仅建议启用 Ubuntu Pro/ESM；CentOS Linux 7/8、Amazon Linux 2、Alibaba Cloud Linux 2 和 openSUSE Leap 15.x 等停止维护版本不纳入默认支持。
- Docker 路线用 Docker Engine / Desktop 与 Compose，固定 Compose 项目名 `repair-marketplace`；Kubernetes 路线 Linux 使用 K3s，macOS / Windows 使用 Minikube v1.39.0。Windows Minikube 当前无 ARM64 官方二进制，因此该架构只支持 Docker 路线。两条路线共用 Go 镜像与 TiDB / API 配置。
- 当前部署镜像使用 Go 1.26.8、TiDB v8.5.8 单机 `unistore` 演示模式；容器启动时由迁移程序创建数据库并执行 SQL 初始化。默认 API / TiDB 只映射到本机，演示 API 没有认证，配置只能用于本机预览 / 单机验证，不能直接暴露公网或视作生产高可用方案。
- Windows、macOS、Linux 的脚本均按芯片选择支持的二进制；Linux 需要 sudo/root，macOS 首次 Docker Desktop 安装需系统授权与接受许可，Windows 可能需要安装 WSL 2、UAC 或重启。Docker Desktop 要求、Minikube 发布资产和云厂商镜像版本都可能变化，后续修改前应核对官方支持矩阵。部署脚本目前仅做文件结构和说明的静态对账，尚未在各目标系统实际执行安装。
