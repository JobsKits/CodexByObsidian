## 二、范围与副作用

- 默认只改用户要求范围内的文件，保留并绕开已有或并发改动。
- 格式化或清理任务不顺手执行构建、安装、重生成或其它有副作用流程，优先保守编辑和针对性验证。
- 所有代码任务默认只修改 Jobs 本人编写或已明确由 Jobs 接管维护的源码；第三方 Pod、手工引入源码、供应商源码、生成代码和文件头 / 版权 / 路径显示为他人作者的源码一律不改，即使它位于项目或本地 Pod 内也继续排除。
- 标准 Jobs 文件头、仓库历史或用户明确指定可以作为所有权依据，仅有目录名不能证明所有权；所有权不明确时先排除并报告，只有用户明确点名授权后才处理。

## 三、跨仓库处理

- 当任务同时点名 Swift 侧、OC 侧新旧代码且范围是“我写的代码”时，默认在已命名仓库中做一次跨仓库完整处理，不缩小成单文件或单语言。
- Swift 与 Objective-C 同时命中时，新旧仓库的清理规则要在同一批次保持对齐。

## 四、iOS UI 引用预埋

- 来源：用户于 2026-07-21 明确确认。Swift / Objective-C 中凡进入页面层级、绑定约束 / 事件 / 代理、参与页面生命周期或未来可能修改的 UI / 交互对象，默认提升为所属类型的属性，不长期留在方法局部变量中；目的是随时取得引用，为刷新、显隐、换肤和重配预留入口。
- 固定对象使用单一属性；重复动态 UI 使用带元素类型的数组或字典属性统一持有。只排除系统回调已传入的复用对象、Jobs 工厂 / DSL 底层封装临时对象和没有后续修改语义的纯计算临时值。

## 七、Swift / OC 应用层“一镜到底”

- 来源：用户于 2026-07-27 先确认 OC“一链到底”，并于 2026-08-03 明确扩展为 Swift / OC 共用的“一镜到底”。Swift、OC 新工程与 OC 老工程的 Jobs 自维护代码中，所有支持 Jobs 点语法 / 链式语法的对象都遵守该规则，范围不限于 `UIButton`，还包括 View、Control、Layer、Cell、Model、配置对象、请求对象和业务基础对象。
- 同一连续配置语义中主接收者只作为链起点出现一次；Swift 子对象优先使用宿主级 `byXxx` / 配置闭包，OC 子对象优先使用 `byXxxBlock` 回到主链。以 `UITableViewCell` 为例，调用端不重新起 `cell.textLabel`、`cell.detailTextLabel`、`cell.imageView` 或 `cell.contentView`，而从 Cell 级标题、副标题、图片和子对象闭包 API 继续点出。
- 缺少链式入口时先在真实归属层补齐返回 `Self` 的 DSL，再修改调用端。链序按具体类型到通用类型排列；终止动作放在链尾，多个返回 `void` 的终止动作分别调用。真正查询、控制流、SnapKit / Masonry 构建器及无法保持主对象返回类型的第三方回调按真实语义独立表达。
- 同类整改覆盖用户点名的 Swift / OC Jobs 自维护范围，排除外部 `Pods/`、`ManualBy*Pods@Pods/`、手工第三方、生成代码和非 Jobs 所有源码，并以对应 workspace 的真实编译验证链序、类型与行为。
- 来源：用户于 2026-08-07 明确确认为重要代码习惯。Swift、OC 新工程和 OC 老工程的 Jobs 自维护调用方创建 Apple 系统类时，必须先进入同类型的 Jobs 类级创建 DSL；无参构造走“创建 + 配置 Block / closure”，带参构造由真实类型的类级初始化 DSL 承接。裸系统构造只允许存在于对应工厂底层。
- 实例创建后的系统属性、无入参实例方法和单入参实例方法全部由真实类型的 `byXxx` DSL 承接，并在非查询、非终止语义下返回当前具体类型继续链；缺创建或实例 DSL 时先补底层，再修改调用方。
